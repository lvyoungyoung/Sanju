# 自定义学习主题的 AI 复核

更新时间：2026-09-20

## 收录规则

推荐分类主题依然按分类 ID 精确匹配，收藏依然由用户手动选择。本次只改没有分类 ID 的自定义主题。

1. 语义初筛：继续使用现有百炼向量，余弦相似度至少为 0.42，比较范围限同一账号、相同向量模型。
2. AI 复核：MiMo 根据主题名称、英文原句和中文翻译逐句判断，明确贴题才通过。不发送图片。
3. 正式收录：只有已通过复核的关联才写入 study_scene_sentences；候选、待处理和已排除的句子均不进入主题或学习队列。

这取代了上一轮尚未部署的“0.55 + 最高分差 0.10”方案。相似度现在仅用于召回，不再作为收录依据，也不会因为出现更高分的新句子把原来已通过复核的句子挤出去。

提示词强调：直接学习价值、句子本身的证据、具体主题的限定条件；排除泛泛的感受、社交套话和缺少场景依据的通用描述。不允许为了贴题而虚构照片背景，不凑数量，允许全部排除。主题和句子作为不可信数据提供，不能作为指令执行。

仍存在模型误判以及语义初筛漏召回的可能。这不是词性或语法结构检索功能；上线前需用真实主题与正反例评估，不应把离线程序测试理解为匹配准确率测试。

## 缓存、安全和重试

- 新表 study_scene_sentence_reviews 保存候选、输入指纹、相似度、通过/排除结果、简短原因、重试时间与处理租约。客户端无直接读写权限。
- 指纹包含复核规则版本、主题名称、英文和中文，未改变的正反判断都会缓存。重复刷新不重复调用 AI。
- 每批最多 20 条，每位用户同时最多一个批次；数据库租约为 60 秒。模型请求包含读取响应体在内最多 15 秒。
- 服务端校验模型返回的索引、数量、布尔值和原因。缺少、重复、伪造的索引或不完整回复会使整个批次失败，不会部分放行。
- 所有实际句子 ID、主题 ID 和租约来自数据库，而非模型输出。写回时再次校验账号、租约、主题类型及当前输入指纹。
- 模型或网络失败时保留待复核，按 30 秒起步、最多一小时的退避时间重试，不退回“仅靠向量直接收录”。
- 进程中断后租约到期可重试；旧进程迟到的回复不能覆盖新结果。已通过的其他句子仍可正常学习。

## 触发时机

- 创建主题：原 create-study-scene 仍生成主题向量，数据库原 RPC 现在只建立待复核候选。客户端随后进入详情，分批调用 review-study-scene。
- 后续生成：generate-memory-v2 在原子化保存/扣次数和向量入库之后，尝试在后台处理最多三批。运行环境不支持 EdgeRuntime.waitUntil 或后台中断时，待处理记录仍在库中。
- 匿名内容：匿名生成继续暂存向量；登录后导入句子时，原数据库触发器把对应候选放入待复核。进入相关主题详情时处理这些候选。
- 主题详情：分批处理待办并刷新已通过的句子。离开页面后停止客户端续批；已经开始的服务端批次仍可安全写回。没有待办时不请求模型。
- 缓存详情和已通过句子可继续显示。复核未完成时显示进度或“部分句子尚未完成筛选”，而不是误报“没有匹配句子”；允许稍后继续筛选。

复核不参与生成结果和扣次数事务，也不删除原句、照片、收藏或学习记录。已有自定义主题的旧关联会在迁移时移出正式列表并重新进入候选，待复核后恢复符合条件的关联。固定分类主题不受影响。

## 部署顺序

1. 先在 staging 应用 20260920000000_review_custom_study_scene_matches.sql。
2. 部署新增 Edge Function review-study-scene；确认可以读取 MIMO_API_KEY 和 MIMO_BASE_URL，以及现有 Supabase 服务配置。沿用项目现有 MiMo 文本接口及 mimo-v2.5，不新增模型供应商。
3. 部署更新后的 generate-memory-v2，启用生成后后台复核。
4. 使用更新后的客户端验证详情页续批、等待、失败提示及匿名导入。
5. staging 验证通过后，再部署 production。

create-study-scene 和 recover-guest-generation 不需要重新部署：它们原来的接口和稳定句子 ID 保持不变。旧 production 客户端只有收藏学习功能，不依赖此新接口；生成响应、扣次数、恢复以及收藏学习 RPC 未改变。包含自定义主题的内部测试客户端应更新，否则不会主动续批。

迁移会为已有自定义主题重新计算候选；数量较大时选择低峰期部署。新表与函数不向 anon/authenticated 开放，只有校验过用户身份的服务端执行。

## 验证

```bash
deno test --no-lock --allow-read --allow-env scripts/tests/
bash scripts/check-edge-functions.sh
```

数据库测试使用内存 PostgreSQL，覆盖实际迁移与 SQL。模型测试使用模拟响应，覆盖严格解析、未知 ID、全部排除、提示词数据隔离、HTTP 错误、超时及无待办零调用。不会读取线上数据或产生模型费用。

这两类检查已接入 GitHub Actions。客户端需通过 iOS 构建和测试。部署 staging 后还应执行 node scripts/check-client-compatibility.mjs，并人工检查真实主题的保留/排除结果。
