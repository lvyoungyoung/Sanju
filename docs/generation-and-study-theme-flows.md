# 生成描述与创建学习主题

2026-10-09 更新：自定义学习主题功能已从客户端移除，下文创建主题流程仅作历史记录。当前第三个 Tab 为“收藏”，直接展示收藏学习统计和句子列表；统计刷新不再请求自定义主题。句子分类、表达用途、向量生成及后端现有接口保留，本次没有后端部署。

核对日期：2026-09-27。本文描述仓库当前实现，不代表线上已部署相同版本。
本轮是职责拆分，不修改提示词、模型、阈值、数据库事务或产品行为。

## 1. 点击“用三句描述一下”

### 手机准备

1. 检查已选图片、网络、余额，以及是否正在恢复上一条任务。
2. 开启生成界面，锁定相关交互；本地检查生成尝试频率。这不是扣除生成余额。
3. 准备模型分析图和回忆保存图，获取有效登录/匿名 session。
4. 生成请求 ID；匿名用户还有 guest job ID。先保存请求 ID、时间、图片及此前回忆 ID，才发送请求，便于中断后恢复。
5. 发起 `generate-memory-v2`，携带分析图、难度、风格、请求 ID 和双组句子格式。

### 云端生成

1. 验证请求方法、配置、用户身份，读取余额和封禁信息。
2. 优先查相同请求的历史结果。已完成直接复用；仍在处理则返回处理中，不再次调用模型。
3. 检查余额、封禁、共享并发名额；原子领取任务执行权，只有领取成功的请求可以继续。
4. 匿名用户先上传恢复用分析图。调用图片审核；明确违规立即停止，当前配置下审核出错/超时放行。
5. MiMo 一次生成两组三句、中译文、每句的场景分类和表达用途。MiMo 失败时才切换 Kimi；两者各最多请求一次。
6. 解析结果、生成稳定句子 ID。分类和表达用途不改变句子的收藏状态，也不会自动创建学习主题。
7. 登录用户上传分析图，再调用 finalize；匿名用户 finalize 已领取的匿名任务。
8. **数据库事务同时保存结果、扣一次余额、完成生成任务、登记后台向量任务。** 图片 Storage 不属于数据库事务。
9. 补写 provider/失败原因等诊断，读数据库中的最终结果，释放并发名额并返回。
10. 启动本次结果的首次后台向量处理，不等待它结束才返回。

### 返回后的两条独立分支

手机收到结果：写本地回忆、更新余额和生成页、清理待恢复标记。登录用户另外尝试上传更清晰的回忆图，失败保留补传队列，不把生成成功改为失败。

云端后台：检查并复用已生成的分类/用途，正常不再调用 MiMo；辅助字段缺失或无效才做纯文本补全。随后并行生成原句向量和用途向量，保存向量并刷新已有学习主题的匹配。匿名向量先存匿名记录，登录迁移时沿用稳定句子 ID。

后台工作不依赖手机继续停留在生成页，但受 Edge Runtime 生命周期限制。失败保留任务状态；现在没有定时重试、创建主题补偿或客户端补全轮询。

### 必须保留的失败边界

- 模型成功不等于数据库保存成功；只有 finalize 成功提交才扣次。
- finalize 请求中断不等于事务回滚，必须保留图片和可恢复状态，不能贸然删除结果或再扣一次。
- 登录结果恢复按用户和请求 ID 查询；匿名恢复按用户和 guest job ID 查询，不重新调用模型。
- 后台向量失败不撤销已生成句子，不再次扣次。
- 匿名的事务保证是“云端可恢复结果与扣次一起提交”，不是手机写盘与云端事务原子提交。

更细的参数、超时与恢复时序见 [图片生成完整链路](image-generation-flow.md)。

## 2. 创建自定义学习主题

### 手机发起

1. 检查登录、网络、非空名称、20 个主题上限；相同名称按已有规则处理。
2. 输入框与创建按钮进入不可重复操作的 loading 状态。
3. 发送 `create-study-scene`，带用户输入的名称；点选推荐主题时还带分类 ID。两者匹配规则相同。

### 云端匹配

1. 检查身份，拒绝匿名用户；校验名称长度 2～24、分类 ID 合法性。
2. 读取该用户主题数量，先拦截已知超限请求，避免浪费向量请求。数据库仍负责并发创建的最终上限。
3. 确认百炼配置。读取按模型和分类版本缓存的公共分类向量，仅缺失时初始化；这不是补全用户历史句子。
4. **直接把原始主题名称生成 query 向量**，不让 AI 改写、解释或扩展名称。
5. 调用数据库 RPC，保存/更新主题及其查询向量，匹配当前账号已有句子，返回主题摘要。

设该主题阈值为 T，入选规则是：

```text
用途相似度 >= T
并且
（原句相似度 >= T 或 所属分类相似度 >= T）
```

默认 T = 0.42，可选 0.36、0.38、0.40、0.42、0.44、0.46、0.48，保存在每个主题上。
分类一路取该句所属分类的最佳匹配。没有用途向量的句子不能仅凭分类入选。
匹配不要求收藏；推荐名称、手动输入名称都用同一套规则。

### 返回与后续

手机收到主题摘要后更新列表、失效该主题旧的详情缓存并进入详情页，再读取句子列表、学习统计和匹配设置。没有匹配句子仍可以保留空主题。

再次进入已有主题以读取数据为主，不重新调用语言模型解释主题；需要准备旧主题匹配时，服务端验证归属并尽量复用查询向量。用户调整匹配范围时，数据库按该主题的新阈值刷新关系。

以后新句子的后台向量成功发布，会刷新与已有主题的关系。创建主题本身不扫描/补全缺失分类、用途、向量，不启动 AI 逐句复核，不扣生成次数。

## 3. 重构后的职责

### 客户端

| 文件 | 职责 |
| --- | --- |
| `AppModel+Generation.swift` | 图片准备、请求上下文、生成调用、结果保存、恢复流程 |
| `AppModel+StudyScenes.swift` | 自定义主题创建/删除、摘要、详情缓存及学习队列 |
| `AppModel+Memories.swift` | 回忆列表、云同步、图片补传、收藏及原有学习记录 |

这次是同一 AppModel 的职责分文件，不新增 manager 或第二份状态。方法体与调用顺序保持不变，不顺带修改当前工作区其他功能。

### 生成函数

| 模块 | 职责 |
| --- | --- |
| `index.ts` | 注册 HTTP 入口、包裹耗时记录 |
| `handler.ts` | 验证、领取任务、按顺序调用阶段，统一失败与释放逻辑 |
| `content.ts` | 类型、分类目录、提示词、解析与返回句子格式 |
| `moderation.ts` | 审核调用、放行/拒绝、违规记录 |
| `providers.ts` | MiMo/Kimi 请求、超时、回退 |
| `persist-result.ts` | 图片上传、登录/匿名结果提交、诊断和最终结果读取 |
| `repository.ts` | 数据库 RPC、任务读取、幂等状态更新、Storage 清理 |
| `responses.ts` | 响应格式、诊断文本和请求值校验 |

结果保存阶段开始 finalize 前通知入口标记“提交已开始”，即使随后抛异常，入口仍知道要保留恢复机会。入口负责释放并发名额和派发后台任务，保存模块不自行启动另一套恢复。

### 创建主题函数

| 模块 | 职责 |
| --- | --- |
| `index.ts` | 注册 HTTP 入口 |
| `handler.ts` | 请求校验、账号权限、数量限制、错误与响应 |
| `matching.ts` | 分类向量缓存、主题向量获取/复用、匹配 RPC |
| `embedding.ts` | 百炼请求、超时、批量顺序、维度与有效性校验 |
| `categories.ts` | 已有公共分类说明与缓存策略，未改 |

数据库继续持有事务、账号隔离和相似度入选规则，不把这些规则复制到客户端或 Edge Function。

## 4. 验证与部署

本地验证包含 Edge Function 类型检查、模拟请求测试、本地数据库事务/匹配回归、iOS 构建和单元测试。HTTP 测试使用实际业务阶段与本地替身，不调用付费模型；本地 SQL 测试不是线上并发压测。

本轮无新 migration、无环境变量或 Nginx 变更。需部署 `generate-memory-v2` 和 `create-study-scene`，目录内模块随函数打包，不是新增的独立 Edge Function。`recover-guest-generation` 和后台向量 worker 未改，不必因本轮重部署。

先部署 staging 再验收；未部署前运行线上兼容脚本只会检查旧服务，不能证明本次重构已生效。前序迁移仍需已按发布流程完成。本轮不自动部署。
